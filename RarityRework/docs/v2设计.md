# 物品稀有度重制 第二版设计（随机词条装备）

## 结论

每件可装备的物品在第一次进入玩家背包时随机一个档位。档位越高，额外词条越多，同时附带一个材质，材质改变模型颜色和名字前缀。词条数据存在 ModData 按存档槽写的文件里，游戏存档本身不改，卸载 mod 后物品回到原版数值。

第二版和第一版放在同一个 DLL 里，设置页切换两种模式。

| 模式 | 行为 |
|---|---|
| 固定档位 | 第一版。每种物品一个固定档位，查分档表 |
| 随机词条 | 可随机的物品逐件掷骰，显示各自的档位、材质和词条；不能随机的物品不显示档位 |

## 哪些物品能随机

| 类别 | 包含 | 改哪个组件 |
|---|---|---|
| 衣物 | 所有可穿戴衣物，含背包、枪套这类配件 | ClothingItem |
| 枪械 | 步枪、左轮、霰弹枪、信号枪 | GunItem |
| 弓 | 所有弓 | BowItem |
| 刀斧和撬具 | 小斧头、猎刀、撬棍、钢锯、猎熊矛、各种简易刀斧 | StruggleBonus、ToolsItem |
| 点火工具 | 打火器、放大镜、弓钻、简易打火器 | FireStarterItem |
| 照明 | 手电、矿工手电、手摇灯 | FlashlightItem |
| 取暖 | 鲸油取暖器 | WhaleOilHeaterItem |
| 药品 | 绷带、药片、消毒剂这类，含背包分类是急救的 mod 药片 | FirstAidItem |

药品按一叠掷骰，一叠共用一个档位。档位不同的同种物品不合并，拆开一叠时拆出来的那份沿用原来的档位。

不随机的有食物、饮料、材料、弹药、箭、火柴、信号棒、火把和剧情物品。子弹装进弹匣后游戏只记弹药类型，分不清哪一发来自哪一盒，所以不做弹药词条。

## 档位怎么掷

| 档位 | 概率 | 词条数 |
|---|---|---|
| 普通 | 45% | 0 |
| 优秀 | 28% | 1 |
| 精良 | 15% | 2 |
| 史诗 | 8% | 3 |
| 传说 | 3.5% | 4 |
| 神话 | 0.5% | 5 |

第一版分档表做保底。表里是史诗及以上的物品（步枪、熊皮大衣、鲸油取暖器这类），随机结果最低是精良。

掷骰时机是物品第一次进入玩家背包，捡起、从容器拿出、自己制作、跟商人换来都算。地上和容器里没被拿过的物品不掷，检视时显示未鉴定。这样载入场景时不会给几百件物品同时掷骰。

随机种子取存档槽名加物品在场景里的标识（没有标识时用名字和位置）。同一件物品读档重捡，结果不变，刷不出更好的词条。

装上 mod 时背包里已有的物品，在第一次载入存档时补掷一次。

## 词条池

背包说明末尾逐行列出词条，名字用原版界面的叫法。能算出绝对值的写成实际加了多少，保留一位小数，括号里是百分比，比如（温暖加成 +0.6°C（+28%））；本身就是倍率的只写百分比。

同一件物品不会重复出现同一个词条。数值在范围内随机，档位越高下限越高，神话的每一条都落在范围上半段。百分比都是相对这件物品的原版数值。

| 类别 | 词条 | 改的数值 | 范围 |
|---|---|---|---|
| 衣物 | 温暖加成 | m_Warmth | +5% 到 +30% |
| 衣物 | 潮湿时温暖加成 | m_WarmthWhenWet | +10% 到 +50% |
| 衣物 | 防风加成 | m_Windproof | +5% 到 +30% |
| 衣物 | 防水性能 | m_Waterproofness | +5% 到 +30% |
| 衣物 | 坚韧程度 | m_Toughness | +5% 到 +30% |
| 衣物 | 干燥速度 | m_DryPercentPerHour、m_DryPercentPerHourNoFire | +10% 到 +60% |
| 衣物 | 状态损耗 | 补丁衣物耐久损耗（日常磨损和被咬都算） | 损耗 -10% 到 -50% |
| 衣物 | 行动力惩罚 | m_SprintBarReductionPercent | 体力条惩罚 -10% 到 -50% |
| 枪械 | 基础伤害 | 每发弹丸设置好基础伤害后，提高这发弹丸的伤害 | +5% 到 +25% |

| 刀斧和撬具 | 打斗伤害 | StruggleBonus.m_DamageScalePercent | +10% 到 +40% |

| 刀斧和撬具 | 场景物件拆解时间 | BreakDownItem.m_BreakDownTimeModifier | 耗时 -10% 到 -40% |
| 刀斧和撬具 | 制造或修理时间 | ToolsItem.m_CraftingAndRepairTimeModifier，按这件工具支持的动作显示 | 耗时 -10% 到 -30% |

| 通用 | 重量 | 物品重量 | -5% 到 -30% |

## 材质

每件随机物品带一个材质。材质只改模型颜色和名字前缀，不换贴图。名字显示成（淬火钢 小斧头）这样。颜色用 MaterialPropertyBlock 叠在地上的模型上，第一人称模型和背包图标不变。

材质跟着档位走，看名字就能认出档位。

| 档位 | 金属件（枪、刀斧、撬棍、手电、取暖器） | 弓 | 衣物 | 药品 |
|---|---|---|---|---|
| 普通 | 锈铁 | 白桦 | 旧料 | 粗制 |
| 优秀 | 熟铁 | 枫木 | 结实 | 常规 |
| 精良 | 精钢 | 橡木 | 精纺 | 精制 |
| 史诗 | 淬火钢 | 白蜡木 | 加厚 | 药厂 |
| 传说 | 黑钢 | 紫杉 | 极地 | 军用 |
| 神话 | 陨铁 | 乌木 | 传世 | 特效 |

衣物和药品只加名字前缀，不改颜色。衣物在纸娃娃界面和第一人称里各有一套贴图，叠色容易出错。

真换贴图（每件物品单独画一套贴图打进 AssetBundle）不在第二版里做，工作量跟物品数量成正比。

## 存档

数据通过 ModData 写进 Mods\ModData\<存档槽>.moddata，条目名 RarityRework_items，内容是 JSON。

```json
{
  "3f2c9a6e-0d4b-4c1e-9a7f-2b8e5d1c6a90": { "t": 4, "m": "淬火钢", "a": { "harvest": 0.27, "struggle": 0.31, "durable": 0.22 } }
}
```

键是物品的 ObjectGuid，游戏把它写进存档里的 m_ObjectGuidSerialized。没有 ObjectGuid 的物品在掷骰时挂一个新的。m_InstanceID 每次读档都会重新分配，不能当键。t 是档位，m 是材质，a 是词条和倍率。

数值在两个时间点套用。一是掷骰当时，二是每次物品从存档载入后（GearItem 反序列化的 Postfix）。载入时字段先恢复成预制体原值，再乘倍率，所以不会越叠越高。

物品被烧掉、拆掉或扔掉后条目不删。每条大约 60 字节，一万件也不到 1 MB。

## 要进游戏验证的事

1. 新挂上的 ObjectGuid 在跨场景搬运、存档读档、放进容器后是否保持不变。这是整个方案的前提
2. 衣物数值改成实例字段后，体感温度和衣物界面是否立即更新
3. 割肉、拆解、耐久损耗没有现成的实例字段，要补丁具体的计算方法，方法名还没反编译确认
4. 制作、商人交易得到的物品能不能正常挂上 ObjectGuid
5. ClothingTweaker2 也改衣物数值。两边都改会互相覆盖或叠加，要定先后

## 已确认

档位概率和词条数按上表。第一版分档表做保底。掷骰时机是第一次进背包，已有物品补掷一次。材质只改颜色和名字。词条范围按上表。
